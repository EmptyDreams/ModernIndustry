## 项目简介

&emsp;&emsp;现代工业（ModernIndustry for MC-1.12.2）是我很久以前就开始设想的项目，不过由于种种原因直到 2019 年才正式开工。

&emsp;&emsp;该项目是我学习 Java 时第一个开工的项目，所以项目里可能残留一些不太好的范式，但是核心逻辑已经重构了许多遍了。

## 项目现状

&emsp;&emsp;目前项目已经弃坑，除了用于测试的物品/方块样例，并没有开始进行游玩内容的开发。所以现在模组实质上是一个前置包，内部包含了多种 API 的实现，有兴趣的可以参考一下代码，可以的话点一个 star 谢谢 QAQ。

## 项目亮点

- **高性能电力系统**：采用按需供电的设计，避免传统逐段传输模型带来的大量 Tick 计算，使电力网络的运行开销主要取决于实际用电需求，而非导线数量。通过统一管理跨区块线路，减少对沿途区块加载状态的依赖，避免为传输电力而强制加载中间区块。同时针对线路频繁连接、断开等场景进行优化，尽可能避免全网重新计算，使大规模动态电网也能保持较低的维护成本。

- **声明式 GUI 框架**：借鉴 Web 前端开发理念，将界面结构、样式和业务逻辑分离，解决传统 Minecraft GUI 开发中布局繁琐、代码耦合严重、复用困难等问题。支持组件化开发、自动布局和运行时渲染，使复杂界面的开发与维护更加方便。

- **自动化注册与数据持久化**：针对 Forge 开发中大量重复的注册和数据读写工作，提供基于注解的自动化解决方案。开发者可以专注于业务逻辑，减少样板代码，同时保持良好的扩展性。

- **独立合成系统**：摆脱原版合成机制的限制，允许不同机器拥有独立的合成规则，支持复杂输入匹配、自定义产物属性与数据驱动配置，为工业生产链提供灵活的基础支持。

- **流体管道系统**：引入动力消耗机制，使流体运输不再只是简单的容量转移，同时支持从世界中抽取流体，为更复杂的流体生产与运输系统提供基础。

- **自动化网络通信**：统一封装客户端与服务端的数据交互，简化消息发送、处理与状态同步，并针对消息处理时目标暂不可用的情况提供重试机制，降低网络通信开发的复杂度。

## 给新人的话

ModernIndustry 是我真正意义上的第一个项目。虽然它最终没有完成，但在开发过程中，我的编码能力、程序设计和架构设计水平都得到了实实在在的提升。这段经历也让我逐渐认识到，程序设计不仅是解决问题，更重要的是学会取舍。

在开发过程中，我曾花费大量时间研究电力损耗、流体物理等机制，希望尽可能真实地模拟这些行为。然而，复杂并不意味着优秀，真实也不一定意味着有趣。比如《机械动力》就舍弃了传输损耗，让玩家能够自由地设计和布置动力网络，而不必时刻担心额外的损失。对于玩家而言，某些看似合理的限制，可能只是增加了心智负担，却没有带来相应的乐趣。

这个项目最终也因为流体物理系统的开发困难而长期停滞，直至彻底弃坑。回头来看，我并不后悔当初的技术探索，但如果重新开始，我会更加认真地考虑每项设计的收益与代价。

技术上的复杂性可以是实现目标的手段，但不应该成为目标本身。
